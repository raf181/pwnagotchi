# Known Differences from Python

The Go daemon preserves user-visible behavior where practical, but it is not a
line-by-line Python runtime. This document records current, meaningful
differences. Historical migration details remain in `migration-ledger.md`.

## Runtime and Packaging

- The daemon is a static Go binary. Python, pip, and a Python plugin bridge are
  not runtime dependencies.
- Built-in plugins execute in-process as Go packages.
- Third-party plugins execute as separate Go processes using a versioned RPC
  protocol. A bare `.py` file is never loaded.
- Fonts and gettext catalogs are embedded rather than resolved from an
  installed Python package.
- Bettercap and pwngrid remain external services/programs.

## Configuration

- TOML is decoded and encoded with `BurntSushi/toml`, not `tomlkit`. Values are
  preserved, but comments, hand formatting, and key order are not guaranteed
  after a rewrite.
- Config saves are now atomic and preserve the existing file mode and
  ownership. This intentionally improves on truncate-in-place paths that could
  destroy a working config after an encoding/write failure.
- Runtime web edits still target `/etc/pwnagotchi/config.toml`; a daemon
  started with a non-default `--user-config` path does not redirect web writes
  to that path.
- Legacy YAML and dotted-TOML conversion remain supported.
- `main.custom_plugins` is retained only for legacy-file diagnostics.
- The three stale default sections for nonexistent `gps_listener`, `pwndroid`,
  and `ups_hat_c` plugins were removed.

## CLI

- Main help text intentionally follows the former argparse surface, but it is
  generated by Go code rather than argparse.
- `pwnagotchi plugins`, `plugins --help`, and each plugin subcommand now return
  useful help with exit status 0.
- Plugin install/update uses manifests and compiled executables, not ZIP files
  containing Python.
- `plugins doctor` is a Go-only, non-destructive validation command.
- The bundled `auto-update` plugin checks by default, but privileged binary
  installation is opt-in. Bettercap/pwngrid updates require a matching
  checksum sidecar and retain the old executable until the service restarts.
  The running Pwnagotchi daemon is never self-replaced in-process; update it
  through the deployment procedure.

## Plugin Semantics

- In-process plugins receive narrow capability interfaces rather than concrete
  Python objects.
- Events use one `HandleEvent` switch rather than dynamically locating
  `on_<event>` methods.
- Event queues are bounded. A slow handler can drop new events instead of
  stalling the entire daemon.
- A panic in an in-process event callback is recovered; Python relied on
  exception handling around dynamic dispatch.
- Remote event arguments cross JSON and therefore lose Go concrete types.
- Remote plugins expose only `Log`, `Agent`, `View`, `Exec`, and `Clock`.
  Remote webhooks, GPIO, I2C, SPI, and system actions are not available over
  RPC.
- SHA-256 checksums are mandatory for remote executables, but manifests and
  indexes are not signed.
- Capability declarations are RPC allowlists, not operating-system sandboxing.

## Web UI and Security

- The web server is `net/http`, not Flask/Werkzeug/Jinja. HTML and response
  header ordering are not byte-identical.
- CSRF uses a double-submit cookie/header-or-form token rather than Flask-WTF
  sessions.
- Inbox mutation, plugin toggles/upgrades, Bluetooth actions, and similar
  state changes use POST instead of GET.
- Generic unsafe plugin webhook requests are checked centrally for CSRF.
- Packaged defaults now enable Basic authentication. This is a deliberate
  security change from configurations that exposed the UI without auth.
- Default placeholder web credentials still have to be changed; startup logs a
  warning when auth is disabled or placeholders remain.
- HTTP read, write, idle, header, and selected body limits are explicit.
- CORS is only enabled for an explicitly configured origin.

## Rendering and Displays

- Canvas composition, fonts, widgets, web frames, and `DummyDisplay` are
  implemented in Go.
- Go's font rasterizer does not produce byte-identical pixels to Pillow at all
  sizes. Layout and readable output are the compatibility target.
- The display registry recognizes the Python display names and layouts, but
  approximately 92 physical driver implementations remain unsupported.
- When a physical driver cannot initialize, the daemon uses the headless view.
  It does not pretend that panel I/O succeeded.
- `weact2in9` remains a special registry inconsistency inherited from the
  Python dispatch table and is surfaced as an explicit error.

## Hardware

- Linux I2C is implemented through `/dev/i2c-*` and `I2C_RDWR`; this differs
  from Python libraries but preserves register read/write behavior.
- Linux GPIO uses the legacy sysfs ABI because it is available on the target
  image. It does not set pull-up or pull-down bias.
- SPI and generalized PWM are not implemented.
- The stock Pi Zero 2 W onboard `brcmfmac` radio does not expose monitor mode.
  A compatible Nexmon build or supported USB adapter is required.

## Logging

`internal/logging` implements configuration and rotation, but many packages
still call the standard library `log` package directly. As a result, not every
line follows the former Python formatter or all configured handler levels.
Completing this migration requires routing package logs through the configured
logger without creating import cycles.

## External Commands

Most commands use explicit executable/argument vectors, removing shell
interpolation. Shell execution remains intentional where the configuration
itself represents a shell program:

- display `on_frame`
- `switcher` task command scripts

These fields are administrator-controlled code and must be treated accordingly.

## Preserved Compatibility Quirks

Several odd Python behaviors remain because changing them would alter existing
config or data contracts:

- version segments are compared lexically in the compatibility parser
- selected display aliases preserve the original normalization table behavior
- identity public-key PEM preserves the historical header/body combination
- grid's disabled-advertise path preserves its old path construction
- selected status/session parsing edge cases retain Python output

These are covered by focused tests where the behavior remains relevant.

## Plugin-Specific Limits

- `bt-tether` cannot fully reproduce an interactive long-lived
  `bluetoothctl` pairing agent through the request/response command capability.
- `pwnstore_ui` can browse store data and edit config, but cannot install a
  legacy Python store entry.
- `auto-update` can install verified bettercap/pwngrid releases when explicitly
  enabled, but only reports Pwnagotchi daemon releases.
- `gps` files may omit WiGLE accuracy/update fields; `wigle` applies safe
  defaults.
- Hardware plugins require real I2C/GPIO devices and appropriate wiring.
- UI plugins render to web/headless state, but no physical panel is currently
  driven by the Go display layer.

## Live Deployment Boundary

The Pi inspected on 2026-07-26 runs an older dirty binary than this source
tree. Fixes documented here are source-tree behavior until a new arm64 binary
is built and deliberately deployed. See `deploy/README.md`.
